# Формат обмена SchemaAnalyst → C++

Версия формата: `1`.

Корневые поля:

- `formatVersion` — номер версии;
- `snapshotSha256` — SHA-256 исходного `.ser`;
- `generation` — критерий, генератор, seed, бюджет и измерения генерации;
- `schema.tables` — таблицы, столбцы и Java-типы;
- `schema.checks` — структурированные CHECK;
- `requirements` — требования покрытия SchemaAnalyst;
- `tests` — тесты, их строки, SQL и покрытие.

## CHECK

Поддерживаемый CHECK имеет `supported=true`, оператор из `<`, `<=`, `>`, `>=` и два операнда. Операнд имеет `kind=column` либо `kind=constant`. Для неподдерживаемого выражения сохраняются исходная строка и `unsupportedReason`.

## Тест

Тест содержит:

- устойчивый идентификатор `T1`, `T2`, ...;
- `sourceRequirementId`;
- список `coveredRequirementIds`, рассчитанный независимо от descriptors;
- ожидаемый результат;
- строки `state` и `data`;
- SQL для внешней проверки PostgreSQL;
- раздельное число state/data INSERT.

Значения ячеек передаются строками, чтобы точно сохранять `BIGINT`. SQL NULL передаётся JSON `null`.

## Подтверждение PostgreSQL

После выполнения набора валидатор добавляет к каждому тесту `postgresValidation`:

- `phase` — `data`, `state`, `reset` или `missing`;
- `actualResult` — фактический результат данных; `null`, если он не был измерен;
- `sqlstate` — SQLSTATE первой ошибки, если вставка завершилась ошибкой;
- `constraintName` — имя ограничения, извлечённое из сообщения PostgreSQL.

Boundary-coverage засчитывает успешную вставку данных, если она совпала с ожидаемым результатом. Ожидаемый отказ засчитывается только конкретному CHECK, если PostgreSQL вернул SQLSTATE `23514` и `constraintName` совпадает с идентификатором этого CHECK. Отказ из-за другого ограничения не является свидетельством границы этого CHECK; такой тест попадает в `unverifiedBoundaryTestIds` и не расширяет множество подтверждённых границ.

Экспорт не выполняет генерацию повторно: он читает сохранённый снимок. Разные алгоритмы сокращения должны ссылаться на одинаковый `snapshotSha256`.
