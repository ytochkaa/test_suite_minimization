# Проверенное состояние практической части

Дата проверки: 17.11.2026.

## Что есть в репозитории

- Исходный код SchemaAnalyst версии `9002b68e44b737349692643ca9efdac2bf1b8b8b`.
- Генерация `TestRequirements` и `TestSuite` на Java.
- Штатные методы сокращения `simpleGreedy`, `additionalGreedy`, `HGS`, `random` и `sticcer`.
- Документ с UML и проектом будущего сохранения граничного покрытия в `README.md`.

## Что подготовлено отдельно от репозитория

В каталоге `schemaanalyst_experiments` рабочей папки подготовлены:

- `CourseworkSchema.java` — Java-представление небольшой схемы PostgreSQL;
- `Experiment.java` — незавершённая обвязка генерации и сокращения;
- `schema.sql` — соответствующая SQL-схема;
- `manual_null_oracle.sql` — ручная проверка трёхзначной логики;
- `run.ps1` — сценарий матрицы запусков.

Эти файлы не являются частью текущего репозитория `test_suite_minimization`.

## Что подтверждено запуском

- SchemaAnalyst собран на Windows с Eclipse Temurin JDK 8u512-b09 и Gradle 4.10.2. Сборка завершилась сообщением `BUILD SUCCESSFUL in 1m 26s`.
- `CourseworkSchema.java` и `Experiment.java` скомпилированы с кодом завершения 0.
- Для проверки создан отдельный локальный экземпляр PostgreSQL 18.7 на `127.0.0.1:55432`.
- В PostgreSQL выполнен `manual_null_oracle.sql`. Во всех семи строках вычисленный признак принятия совпал с ожидаемым.

Ручной oracle проверяет выражение `((x > 0 AND y > 0) IS NOT FALSE)`. Он не является запуском сгенерированного набора SchemaAnalyst и не доказывает корректность внутреннего oracle проекта.

## Ограничение выводов

Статический анализ показывает, что штатные требования покрытия не задают обязательную тройку значений перед границей, на границе и после неё. Из этого следует только возможность потери отдельной граничной проверки. Утверждать, что штатные методы действительно теряют границы, можно лишь после сравнения на одинаковых исходных наборах.
